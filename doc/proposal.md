# 视频片段标注平台需求文档

> 文档定位：本文件定义产品需求，作为后续概要设计、模块详细设计、Vibe Coding 最小任务及起始 Prompt 的输入。不在此文档中预设技术架构、接口或数据库方案。
>
> 需求来源：题目 README 及逐项需求确认。未在 README 中规定且尚未确认的内容不作为已确定需求。

## 1. 项目背景

数据团队需要从机器人示教视频中标出有用片段。当前通过表格记录片段起止时间，再由管理员每天手工汇总，容易出现统计不一致。需要建设一个 Web 应用，支持按租户隔离的视频任务分配、时间段标注、提交和每日有效工作量统计。

## 2. 项目目标

1. 管理员能够创建租户、账号和标注任务，并为任务指定租户、视频及可选截止时间和标注说明。
2. 标注员能够查看本租户任务、领取任务、在视频中标出多个时间段并提交。
3. 系统能够阻止无效或相互重叠的时间段，并只将有效提交计入工作量。
4. 管理员能够按提交日期查看每日有效时长，并追溯到租户、标注员、任务和时间段。
5. 租户间的数据隔离必须由后端执行。

## 3. 用户与权限

### 3.1 平台管理员

- 可管理所有租户。
- 可创建、查看和停用租户。
- 可在应用内创建管理员账号和标注员账号；创建标注员账号时指定其所属租户。
- 可创建、发布和取消标注任务。
- 可退回已提交任务以便纠错。
- 可查看全平台每日工作量统计，并展开查看租户、标注员、任务及片段明细。

### 3.2 标注员

- 使用账号密码登录，账号由管理员预先创建，并绑定一个租户。
- 只能访问所属租户的数据；跨租户隔离由后端保证。
- 可领取本租户可领取的任务，已被其他标注员领取的任务不可再领取。
- 可退回自己领取但尚未提交的任务，使其重新变为可领取。
- 可对领取的任务添加、编辑和删除时间段，并提交任务。
- 管理员退回任务后，可在保留的原片段上修改并重新提交。

## 4. 核心业务流程

### 4.1 管理员发布任务

1. 管理员选择租户并填写必填任务名称。
2. 管理员填写浏览器可直接播放的公开视频直链。
3. 管理员可选填标注说明和截止时间。
4. 发布后，任务出现在对应租户的可领取任务列表中。

### 4.2 标注员完成任务

1. 标注员登录后只看到自己租户的数据。
2. 标注员领取一个可领取任务。
3. 标注员播放视频并添加一个或多个时间段。
4. 标注员可调整或删除尚未提交的片段。
5. 系统验证片段有效且彼此不重叠后，标注员提交任务。
6. 提交成功后任务进入已提交状态，标注员不能自行修改。

### 4.3 退回与重新提交

1. 管理员可退回已提交任务以便纠错。
2. 任务退回后，原片段保留供标注员修改。
3. 退回期间，该任务原提交结果暂时不计入有效时长。
4. 标注员修正后重新提交，修正后的时长计入重新提交日期；原提交日不再计入该任务的时长。

### 4.4 管理员统计

1. 管理员按日期查看每日有效时长总量。
2. 管理员可展开查看租户、标注员、任务及该任务的片段明细。
3. 统计日期使用中国标准时间（Asia/Shanghai）。

## 5. 功能需求

### 5.1 登录与账号管理

- FR-001：系统应支持账号密码登录。
- FR-002：平台管理员应能创建管理员账号和标注员账号。
- FR-003：创建标注员账号时应指定其所属租户。
- FR-004：平台管理员应能停用账号。停用后用户不能登录，历史任务及统计记录应保留。
- FR-005：本地演示环境应预置一个平台管理员账号、一个演示租户和一个该租户的标注员账号，以便直接体验完整流程。演示凭据应为虚构凭据并写入启动说明，不使用真实秘密。

### 5.2 租户管理

- FR-006：平台管理员应能创建、查看和停用租户。
- FR-007：停用租户后应保留其历史数据，并禁止该租户用户登录、领取任务或提交任务。
- FR-008：标注员只能看到并操作所属租户的数据；后端应对列表、详情、领取、保存、提交等操作执行租户权限校验。

### 5.3 任务管理

- FR-009：管理员应能创建并发布任务，任务必须指定租户、任务名称和视频 URL。
- FR-010：任务标注说明为选填字段。
- FR-011：任务截止时间为选填字段；未设置时任务没有截止日期。
- FR-012：超过截止时间的任务应标记为逾期，但仍允许领取和提交。
- FR-013：管理员应能取消任务。未领取任务可直接取消；管理员对已领取但未提交的任务执行取消时，系统应在同一操作中解除领取并将任务置为取消状态。已提交任务不能取消。
- FR-014：每个任务同一时刻最多由一名标注员领取。
- FR-015：标注员可将尚未提交的已领取任务退回为可领取状态。
- FR-016：管理员可退回已提交任务；退回后任务进入待修正状态，原片段保留，允许标注员修改和重新提交。

### 5.4 视频与片段标注

- FR-017：任务视频通过浏览器可直接播放的公开视频直链提供。
- FR-018：标注员应能在任务视频上添加多个时间段。
- FR-019：时间段起止时间使用毫秒精度。
- FR-020：标注员应能编辑和删除未提交任务中的片段。
- FR-021：管理员退回任务后，标注员应能在原片段基础上修改。
- FR-022：视频时长可用后，系统应使用其校验片段时间范围。无法获取视频总时长时，系统应跳过片段是否超出视频时长的校验，仍强制执行其他片段校验，并明确提示标注员视频边界未能校验。

### 5.5 提交与统计

- FR-023：任务至少包含一个有效片段才允许提交。
- FR-024：只有当前已提交状态的任务计入有效时长；未提交或已退回待修正的任务不计入。
- FR-025：有效时长为已提交任务内所有片段时长之和。
- FR-026：有效时长归属任务最近一次成功提交日期，日期按 Asia/Shanghai 计算。
- FR-027：管理员每日统计应支持查看总量，并展开到租户、标注员、任务和时间段明细。
- FR-028：提交后标注内容锁定；需要修改时由管理员退回任务。
- FR-029：统计结果应反映当前有效提交及其片段；管理员退回任务后，该任务暂不计入统计，重新提交后按修正后的片段和提交日期计入。

## 6. 业务规则与数据校验

- BR-001：同一任务中的时间段不得重叠；首尾相接允许。例如 `[10s, 20s]` 与 `[20s, 30s]` 合法。
- BR-002：每个时间段必须满足起点小于终点。
- BR-003：片段起点和终点必须位于视频时长范围内。
- BR-004：任务必须至少包含一个有效片段才能提交。
- BR-005：时间段规则必须在后端校验，不能只依赖前端。
- BR-006：领取动作必须保证同一任务不会被多个标注员同时成功领取。
- BR-007：租户隔离必须在后端执行，不能依靠前端隐藏数据。
- BR-008：只有有效提交结果参与统计；管理员退回后原结果暂时移出统计。
- BR-009：退回任务重新提交后，原提交日期撤销该任务时长，修正后的时长记入重新提交日期。
- BR-010：时间精度为毫秒。片段时间表示相对视频起点的播放时间，不进行时区转换；仅统计归属日期按中国标准时间（Asia/Shanghai）计算。
- BR-011：管理员收回或取消任务与标注员保存或提交并发时，系统必须以原子状态转换决定结果。收回或取消先成功后，该标注员对任务的后续保存、提交请求必须被拒绝；若提交先成功，任务进入已提交状态，不能再按未提交任务收回或取消，应按已提交任务退回流程处理。
- BR-012：无法获取视频总时长时，跳过片段超出视频时长的校验并向标注员明确提示；起止关系、重叠和至少一个有效片段等其他规则仍必须校验。

## 7. 输出与页面需求

### 7.1 标注员工作界面

- 展示本租户可领取任务及本人已领取任务。
- 提供视频播放和片段编辑操作。
- 展示片段起止时间及当前任务片段总时长。
- 清晰呈现任务状态、截止时间或逾期状态、提交结果和校验错误。

### 7.2 管理员界面

- 提供租户、账号和任务管理入口。
- 展示每日有效时长总量及可追溯明细。
- 明细至少能够追溯到租户、标注员、任务和已提交片段。

### 7.3 交互体验

- 视频标注界面应适合标注员每日重复使用，时间信息和片段状态应易于辨认。
- 常见操作应有明确的成功、失败、加载和空状态反馈。
- 视觉和操作体验属于本题评估内容，应在实现和验收中检查。

## 8. 演示数据要求

- 默认测试视频使用 Push-T 推方块视频，公开下载文件约 7 MB。
- ALOHA 双臂做咖啡视频约 500 MB，可作为可选测试数据，不作为默认演示视频。
- 演示环境应提供能够直接体验完整流程的管理员、租户和标注员。

## 9. 验收标准

1. 本地启动后可使用启动说明中的演示管理员账号登录。
2. 管理员可以创建租户、创建该租户的标注员账号，并发布包含名称和公开视频直链的任务。
3. 标注员只能访问自己所属租户的任务；尝试通过接口访问其他租户任务时，后端拒绝访问。
4. 两个标注员并发领取同一任务时，最多一人领取成功。
5. 标注员可以创建多个毫秒精度的片段；重叠、零长度、倒置及超出视频时长的片段不能提交。
6. 首尾相接的有效时间段可以通过校验。
7. 无片段任务不能提交；提交后任务和片段被锁定。
8. 视频时长不可获取时，系统提示边界无法校验，但仍拒绝起点不小于终点、重叠或无有效片段的提交。
9. 未提交和退回待修正任务不计入统计；当前有效提交的片段时长之和计入统计。
10. 管理员退回任务后原片段保留、原统计暂时移除；重新提交后时长归入重新提交日，旧提交日不再计入该任务时长。
11. 每日统计按 Asia/Shanghai 的提交日期归属，并能展开到租户、标注员、任务及片段明细；片段时间作为视频相对时间处理，不做时区转换。
12. 逾期任务仍可领取和提交；停用账号或租户后相应用户不能登录或继续操作，但历史记录保留。
13. 管理员执行取消已领取但未提交的任务时，系统在同一操作中解除领取并取消任务；已提交任务不能取消。
14. 并发时收回或取消先成功，则之后的保存、提交请求被拒绝；提交先成功，则任务只能按已提交任务退回流程处理。
15. 标注员可以退回未提交任务，任务重新可领取。

## 10. 明确不属于本需求文档的内容

本文件不规定具体技术栈、系统架构、数据库表结构、接口协议、部署平台或模块代码实现。这些内容应在后续概要设计和详细设计阶段确定，并据此拆分 Vibe Coding 最小任务及起始 Prompt。

本需求不要求保存片段修改历史；系统只需提供当前有效的一套时间段。统计的具体实现方式（例如实时计算或预聚合）由后续概要设计确定，但统计结果必须符合本文件规定的有效提交口径。
