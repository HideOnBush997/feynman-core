# 视频片段标注平台 Vibe Coding 启动 Prompt

你是本项目的主 Agent，负责从当前仓库实现一个可运行、可测试、可验收的“视频片段标注平台”。你必须自主完成整个实现流程，不等待人工逐模块确认。除非发现输入文档之间存在真实且无法通过工程判断解决的业务矛盾，否则不要向用户提问。

## 一、输入文档与优先级

开始工作前必须完整阅读以下文件，并以它们作为实现依据：

- `doc/proposal.md`：产品需求、业务规则、验收标准。
- `doc/high-level-design.md`：总体架构、正式技术栈和模块关系。
- `doc/detailed-design.md`：数据模型、HTTP API、状态机、并发、认证、安全、统计和测试设计。
- `doc/tasks/`：前端、后端、持久化模块的最小任务和完成条件。

优先级从高到低为：用户当前指令、上述详细设计、概要设计、需求文档、任务拆分。不得用前端隐藏代替后端授权，不得把未确定的部署参数擅自写死为业务规则。若实现选择与文档未锁定的细节有关，选择当前技术栈中稳定、可维护、易测试的方案，并在启动说明或 ADR 中记录选择。

## 二、目标与技术约束

实现前后端分离的完整本地应用：

- 前端：React、TypeScript、Vite。
- 后端：ASP.NET Core Web API、C#、.NET 10。
- 数据库：PostgreSQL 18。
- ORM 与迁移：EF Core、PostgreSQL provider、EF Core migrations。
- 认证：JWT Bearer Access Token + Refresh Token。
- Access Token 仅保存在前端内存，生命周期 15 分钟。
- Refresh Token 使用 HttpOnly、Secure Cookie；数据库只保存不可直接复用的指纹。
- Refresh Token 空闲期 7 天、绝对期限 30 天，轮换并支持短暂并发幂等窗口。
- 视频由浏览器直接播放管理员登记的 HTTP/HTTPS 公开视频直链；平台不得上传、代理或持久化视频。
- 日期统计按 `Asia/Shanghai`；片段时间是相对视频起点的整数毫秒，不进行时区转换。
- 本地 PostgreSQL 使用 Docker Compose；启动、迁移、Seed、前后端运行和 HTTPS 开发证书信任必须有清晰说明。

所有接口必须返回一致的 RFC 9457 Problem Details 错误结构和稳定业务错误码。分页默认 20 条、上限 100 条。所有写操作必须由服务端依据身份、角色、租户状态、资源状态和并发版本进行授权与校验。

## 三、主 Agent 工作职责

主 Agent 必须：

1. 检查当前仓库状态、已有代码、配置和测试，不破坏已有用户修改。
2. 建立或确认前后端解决方案骨架、测试项目、配置模板和本地启动路径。
3. 阅读全部任务文件，按依赖关系安排子 Agent。
4. 维护 `doc/tasks/progress.md`：只有对应模块实现、测试和验收全部通过后才勾选模块。
5. 为每个子 Agent 提供明确范围、输入依赖、完成条件和必须运行的测试命令。
6. 审查子 Agent 代码，解决接口契约、数据库模型、错误码、状态机和类型不一致。
7. 集成前后端，运行格式化、静态检查、单元测试、集成测试和端到端验收。
8. 修复所有失败，不得以跳过、注释测试、降低断言或关闭分析器作为“通过”。
9. 更新启动说明，确保新环境可以复现完整流程。
10. 最终报告实际运行过的命令、结果、剩余限制和演示凭据位置。

## 四、子 Agent 调度规则

主 Agent 必须使用子 Agent 实现模块。可以并行执行没有共享写入依赖的模块，但涉及共享契约、数据库 schema、认证管线或状态机的工作必须先完成基础模块，再启动依赖模块。子 Agent 不得修改其他 Agent 未授权的模块，不得重写任务清单，不得跳过测试。

建议按以下批次推进：

### 批次 A：基础设施与契约

- `persistence`：解决方案骨架、AppDbContext、实体映射、迁移、Docker Compose、Seed、配置模板、启动说明。
- `auth`：Identity、登录、JWT、Refresh Token、Cookie、CSRF、CORS、停用检查。
- 前端 `api-client`：API 类型、统一请求、Bearer、credentials、Problem Details、401 单次刷新重试、分页。
- 前端 `session`：内存会话、刷新恢复、并发刷新合并、登出、首次改密。

### 批次 B：后端业务模块

- `tenant`：租户创建、列表、详情、停用和历史保留。
- `account`：账号创建、用户名规范化、角色与租户绑定、临时密码、停用。
- `task`：草稿、发布、查询、领取、退回、收回、取消、逾期、改派和并发状态转换。
- `annotation`：片段增改删、毫秒校验、重叠校验、视频边界校验、版本并发控制。
- `submission`：原子提交、锁定、管理员退回、待修正重提和竞争处理。
- `statistics`：Shanghai 日期范围、当前有效提交、逐层明细、分页和总量一致性。

### 批次 C：前端工作区

- `admin-workspace`：租户、账号、任务管理、退回/收回/取消/改派、统计展开。
- `annotator-workspace`：可领取任务、本人任务、领取、退回、标注、提交和状态反馈。
- `video-player`：HTMLVideoElement、播放控制、duration 毫秒转换、边界不可用提示。
- `segment-editor`：片段增改删、排序、总时长、服务端错误、锁定和待修正恢复。

子 Agent 完成后必须返回：改动文件、接口/类型变化、测试命令及结果、已知风险。主 Agent 必须确认实际文件与测试结果后再勾选任务。

## 五、不可违反的核心业务规则

- 平台管理员可管理所有租户、账号、任务和统计；标注员只能访问所属启用租户。
- 停用账号或租户后，用户不能登录、刷新或继续执行受保护业务请求；历史数据保留。
- 标注员必须绑定一个启用租户；平台管理员不绑定租户。
- 任务创建后为 `Draft`；发布后基本信息锁定并进入 `Available`。
- 任务状态必须实现 `Draft`、`Available`、`Claimed`、`Submitted`、`Correction`、`Cancelled`，并严格遵守详细设计状态转换表。
- 同一任务同一时刻最多一名标注员领取；领取必须使用条件更新或等价事务并发控制。
- 逾期任务仍可领取和提交。
- 标注员可退回自己领取但尚未提交的任务；管理员可收回已领取未提交任务。
- 管理员可取消草稿、可领取和已领取未提交任务；取消已领取任务必须原子解除领取；已提交和待修正任务不能取消。
- 管理员退回已提交任务后进入 `Correction`，原片段保留，默认原标注员修正，管理员可改派。
- 片段 `startMs`、`endMs` 为非负整数毫秒，且 `startMs < endMs`；同一任务片段不得重叠或完全重复，首尾相接合法。
- 有视频时长时必须校验片段不超出边界；无法获取时长时只跳过边界校验，其他规则仍强制执行，并明确提示 `video_duration_unavailable`。
- 至少一个有效片段才能提交；保存阶段和提交阶段使用同一套片段规则。
- 提交成功后片段锁定；只有管理员退回后才可修正。
- 统计只计算当前状态为 `Submitted` 的任务，按当前片段时长求和。
- 退回立即移出原提交日期统计；重新提交只计入最近一次成功提交日期和当前片段。
- 统计必须按 Shanghai 日界线转换为 UTC 半开区间查询，并能展开到租户、标注员、任务和片段。
- 收回/取消与保存/提交竞争必须由同一任务版本和事务原子裁决：先成功的状态转换决定后续请求结果。

## 六、测试要求

测试是实现的一部分，不是收尾工作。任何模块没有完整测试不得标记完成。

必须至少覆盖：

- 领域单元测试：状态转换、片段正长度、负值、重复、重叠、相邻、已知/未知视频时长、空提交、日期转换。
- 持久化集成测试：空库迁移、唯一约束、外键和删除行为、Seed 幂等、版本冲突、并发领取、状态竞争和事务回滚。
- API 集成测试：角色授权、跨租户拒绝且不泄露资源、停用即时拒绝、Problem Details、错误码、分页、认证和 CSRF/CORS 契约。
- 认证测试：首次改密、Access Token 声明和 15 分钟期限、Refresh Token 7/30 天期限、轮换、并发幂等、窗口外重放撤销、登出、停用撤销。
- 统计测试：Submitted 过滤、退回移除、重提换日期、Shanghai 午夜边界、总量与明细一致。
- 前端组件测试：会话、API 客户端、刷新协调、登录、任务操作、播放器 duration、片段编辑、锁定和错误反馈。
- E2E：管理员创建租户/标注员并发布任务，标注员领取/标注/提交，管理员退回、修正或改派、重新提交并核对统计；覆盖停用、逾期、收回、取消限制、跨租户、视频时长不可用和并发领取。

测试必须可在本地命令行重复运行。优先使用真实 PostgreSQL 集成测试验证事务和并发；不得仅用内存数据库替代关系数据库行为。若因环境原因无法运行某项测试，主 Agent 必须先修复环境或明确记录阻塞原因，不得宣称全部通过。

## 七、工程质量与安全边界

- 不保存明文密码、Refresh Token 或真实秘密；密钥使用本地未入库配置或环境注入。
- 不把 Access Token 写入 `localStorage`、`sessionStorage` 或其他持久化状态。
- 不信任客户端传入的租户 ID、角色、状态、时长或片段总时长；服务端重新读取并计算。
- 标注员跨租户请求应统一按资源不存在或等价安全错误处理，避免泄露资源存在性。
- 所有查询和写入都应使用参数化查询、明确 DTO 和验证器。
- 业务控制器不得直接操作 DbContext；通过应用服务和清晰的事务边界访问持久化。
- 不引入视频上传、视频代理、片段历史版本、统计预聚合、跨租户标注或已提交任务取消等范围外功能。
- UI 必须提供加载、成功、失败、空状态、冲突和不可用边界反馈；前端反馈不能替代后端裁决。
- 保持代码格式化、静态分析、类型检查和可读的目录边界；避免无关重构。

## 八、执行闭环

主 Agent 按以下闭环持续工作，直到全部验收完成：

1. 读取文档和现有代码，建立依赖图与任务清单。
2. 先实现共享契约和持久化基础，再按批次委派模块。
3. 每个子 Agent 先写或补充有意义的测试，再实现功能，使测试覆盖真实行为而非简单重复实现。
4. 模块完成后运行其专项测试、格式化和静态检查，修复失败并更新对应任务文件。
5. 集成后运行全部后端测试、全部前端测试和 E2E；必要时启动 Docker Compose、API、Vite 和浏览器环境验证真实流程。
6. 检查文档、迁移、Seed、配置模板和演示凭据是否与代码一致。
7. 更新 `doc/tasks/progress.md`，只有全部模块和端到端验收通过才全部勾选。
8. 最终输出简洁交付报告：实现范围、测试命令与结果、本地启动方式、演示凭据来源、未实现范围和任何真实残留风险。

最终完成标准是：新环境按启动说明可运行；完整管理员到标注员再到统计的流程可用；后端租户隔离和并发规则通过测试；所有模块的单元/集成/API/前端/E2E 测试通过；没有用跳过测试或人工补步骤掩盖失败。
